# Sofabaton X 0.7.1

This release lets you pin shortcuts to the sidebar remote's dock and
rename the sidebar entry, and keeps the Control Panel current on its own
when something changes elsewhere. It also fixes display order after
restores and edits, Wifi Commands on hubs added by IP, buttons shared by
two Wifi Devices, and right-to-left languages.

Changes below are relative to integration **0.7.0**, including changes
previously available in the 0.7.1 test releases.

## New

- **Pin shortcuts to the sidebar remote's dock.** Every favorite, macro
  and command in the sidebar remote's sheet now has a pin. Tap it to put
  that item on the dock next to the handle, up to two per Activity (or per
  Device in Device mode). Tap a dock shortcut to send it. Tap the pin of a
  pinned item to pick its icon, swap sides or unpin it. Pins are saved in
  this browser.
- **Rename the sidebar entry.** While the Sidebar Panel is on, the
  **Sidebar Panel** setting shows the entry's name with a pencil next to
  it. The name is the same for everyone and links keep working. See
  [the sidebar](../sidebar.md#-rename-the-sidebar-entry).
- **The Control Panel stays current on its own.** Changes made elsewhere,
  for example in another browser, show up in open Control Panels without
  a refresh. The "Cache was updated externally" banner and its Refresh
  button are gone.
  - An open Activity or Device editor takes over changes made elsewhere
    and keeps your own edits. Where both changed the same thing, your edit
    wins and one line tells you so.
  - While the hub is busy for someone else, the editor waits and catches
    up once when that work is done.
  - If a sync fails halfway, the editor shows what landed, so **Retry**
    only writes what is still missing.
  - While the hub is being written to, every open Control Panel locks, not
    only the one that started the change.

## Fixes

- **Two Wifi Devices can share a button across activities (#306).** For
  example, VOL+ can go to the Amp in Cinema and to the Soundbar in TV.
  Before, saving one device's command took the button from the other in
  every activity, and that device then showed "Sync needed".
- **Wifi Commands work on hubs added by IP (#308).** On a hub added
  manually by IP address, button presses could do nothing. Thanks to
  @cunningplay for reporting and diagnosing it.
- **Restoring a backup keeps its order (#307).** Devices and activities
  come back in the order they had in the backup, not the order the hub
  happened to create them in. The remotes also only start syncing once the
  whole restore has finished.
- **Adding things no longer reshuffles your lists.**
  - A new device, activity or Wifi Device goes at the end, and everything
    else keeps its place.
  - On the X1S, deleting a device no longer shifts the rest of the list.
  - An activity's shortcuts keep your custom order after you add a
    favorite or restore the activity.
  - Deleting commands from a Wifi Device keeps the command order on the
    remote.
- **The X2 remote picks up reorders.** Reordering devices or activities,
  or creating a Wifi Device, now makes the X2 remote sync the change.
- **Wifi Event shortcuts save reliably.** Adding one in the activity
  editor could silently fail when the Wifi Events device had to be
  recreated, for example after a restore or a transport switch.
- **New Wifi Events ask for a sync again.** Once the Wifi Events device
  had been synced, an event you added later looked synced already and
  never showed its "needs sync" badge.
- **X1: activity edits that remove a macro work again.** Removing a macro
  and a favorite in one edit failed although both changes had landed, and
  every later edit of that activity failed the same way.
- **No leftovers from deleted activities.** The hub reuses the numbers of
  deleted activities; a new activity could show the shortcut order of the
  deleted one.
- **Refreshing or syncing a device keeps its cached details.**
  Refreshing a device's commands in the Hub tab dropped its button layout
  and command order from the cache, and syncing changes to a Wifi Device
  could empty its cached command list.
- **Right-to-left languages (Arabic, Hebrew, Persian, ...) work
  properly.** Previously:
  - The hub picker and menus in the Control Panel and the sidebar opened
    in the wrong place, sometimes partly off-screen.
  - The sidebar remote showed its buttons mirrored, for example the
    numpad as 3-2-1 and the color keys in reverse.
  - Back arrows pointed the wrong way.
- Translation updates in every language.

## Updating

1. Update the integration and restart Home Assistant. Existing hubs and
   settings carry forward.
2. Reload open Home Assistant pages to load the updated frontend.
3. If HACS manages **Sofabaton Virtual Remote** separately, update that
   card to **0.2.8** too (translation updates). Updating this integration
   does not replace the HACS-managed card. Otherwise the bundled card
   updates with the integration.

The remote entity no longer has the `cache_generation` attribute. The
Control Panel no longer uses it; if a template or automation of yours
read it, remove that part.
