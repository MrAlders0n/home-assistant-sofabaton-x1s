# Sofabaton X 0.7.1

This release adds shortcuts to the sidebar remote's dock and a configurable
sidebar entry name.
The Control Panel now refreshes automatically; manual refreshes are no
longer needed to display changes. It also fixes display order after
restores and edits, Wifi Commands on hubs added by IP, Wifi Command
button assignments in different activities, and right-to-left layouts.

Changes below are relative to integration **0.7.0**, including changes
previously available in the 0.7.1 test releases.

## New

- **Pin shortcuts to the sidebar remote's dock.** Every favorite, macro
  and command in the sidebar remote's sheet now has a pin. Tap it to put
  that item on the dock next to the handle, up to two per Activity (or per
  Device in Device mode). Tap a dock shortcut to send it. Tap the pin of a
  pinned item to pick its icon, swap sides or unpin it. Pins are saved in
  this browser.
- **Rename the sidebar entry.** While the Sidebar Panel is on, the
  **Sidebar Panel** setting shows the entry's name with a pencil next to
  it. The name is the same for everyone and links keep working. See
  [the sidebar guide](https://github.com/m3tac0de/home-assistant-sofabaton-x1s/blob/main/docs/sidebar.md#-rename-the-sidebar-entry).
- **The Control Panel refreshes automatically.** Changes to hub data and
  Wifi Commands appear in open Control Panels without a manual refresh,
  including changes made in another browser. The "Cache was updated
  externally" banner and its Refresh button have been removed.
  - An open Activity or Device editor incorporates updates while preserving
    your unsaved edits. If an update conflicts with an unsaved edit, your
    edit is retained and a message reports the conflict.
  - While another operation is using the hub, the editor defers its refresh
    until the operation has finished.
  - After a partially completed sync fails, the editor updates to reflect
    the changes already applied. **Retry** applies only the remaining changes.
  - Controls are locked in all open Control Panels while data is being
    written to the hub.

## Fixes

- **Assigning a Wifi Command to a button no longer clears an assignment
  in a separate activity (#306).** For example, in the **Watch a Movie**
  activity, VOL+ can run the **Volume Up** command on the Wifi Device named
  **Soundbar**. In the **Listen to Music** activity, the same button can run
  the **Volume Up** command on a different Wifi Device named **Receiver**.
  Previously, saving the assignment for the Listen to Music activity also
  removed the assignment for the Watch a Movie activity. Both assignments
  are now retained.
- **Wifi Commands work on hubs added by IP (#308).** On a hub added
  manually by IP address, button presses could do nothing. Thanks to
  @cunningplay for reporting and diagnosing it.
- **Backup restores preserve display order (#307).** Devices and activities
  are restored in the backup's display order. Remote syncing starts after
  the entire restore has finished.
- **Wifi Commands work after restoring a backup (#307).** After a restore
  that erased the hub, pressing a Wifi Command or Wifi Event ran no action
  and logged `KeyError: 'default'`. Hubs already in that state are repaired
  automatically the next time Home Assistant reads the hub's device list,
  for example at startup. If the Wifi Device's commands changed after the
  backup was made, the device shows "needs sync" instead; sync it to
  repair it.
- **Creating devices and activities preserves existing display order.**
  - New devices, activities and Wifi Devices are added to the end of their
    lists without changing the order of existing entries.
  - On the X1S, deleting a device no longer shifts the rest of the list.
  - An activity's shortcuts keep your custom order after you add a
    favorite or restore the activity.
  - Deleting commands from a Wifi Device keeps the command order on the
    remote.
- **Reordering devices or activities now triggers an X2 remote sync.**
  Creating a Wifi Device also triggers the sync.
- **Fixed saving Wifi Event shortcuts after device recreation.** Adding
  one in the activity editor could silently fail when the Wifi Events device had to be
  recreated, for example after a restore or a transport switch.
- **New Wifi Events are correctly marked as needing sync.** After the Wifi
  Events device had been synced, newly added events were incorrectly marked
  as already synced and did not show the "needs sync" badge.
- **X1: fixed errors when removing a macro and a favorite.** Removing a macro
  and a favorite in one edit failed although both changes had been applied, and
  every later edit of that activity failed the same way.
- **Deleted activities no longer leave stale shortcut-order data in the cache.**
  The hub reuses activity IDs; a new activity could inherit the cached
  shortcut order of a deleted activity with the same ID.
- **Refreshing or syncing a device keeps its cached details.**
  Refreshing a device's commands in the Hub tab dropped its button layout
  and command order from the cache, and syncing changes to a Wifi Device
  could empty its cached command list.
- **Reduced history database storage.** Home Assistant's history no
  longer stores the remote entity's activity, device and button lists.
  Since 0.5.3 it saved a new copy of a few kilobytes on almost every
  update of the entity. The entity itself still has these attributes,
  and the history still shows the current activity. Copies already stored
  are removed by Home Assistant's normal purge (after 10 days by
  default).
- **Fixed layout issues in right-to-left languages (Arabic, Hebrew,
  Persian, ...).** Previously:
  - The hub picker and menus in the Control Panel and the sidebar opened
    in the wrong place, sometimes partly off-screen.
  - The sidebar remote showed its buttons mirrored, for example the
    numpad as 3-2-1 and the color keys in reverse.
  - Back arrows pointed the wrong way.
- Translation updates in every language.

## Updating

1. Update the integration and restart Home Assistant. Existing hubs and
   settings carry forward.
2. Reload open Home Assistant pages to load the updated frontend.
3. If HACS manages **Sofabaton Virtual Remote** separately, update that
   card to **0.2.8** too. When upgrading from the previous standalone
   release, **0.2.5**, this also includes improved theme and dropdown
   contrast, corrected EXIT-button behavior, and fixes for loading device
   button assignments. Updating this integration does not replace the
   HACS-managed card. Otherwise the bundled card updates with the integration.

The remote entity no longer has the `cache_generation` attribute. The
Control Panel no longer uses it; if a template or automation of yours
read it, remove that part.
